v1.1.1 latest 2026-10-18

Headless System Test, secret masking, hardening.

  • System Test — headless mode: run all 100+ steps without a GUI via python -m modules.system_test.cli --format text|json
  • System Test — CI-ready: correct exit codes and JSON output make it usable as a build gate
  • System Test — proxy port: TestProxy no longer hardcodes 8888 — the OS picks a free port, so parallel runs never collide
  • HTTP Client — masked history: history now stores the request template (Bearer {{vault.token}}) instead of the resolved secret; the actual request is unchanged
  • HTTP Client — response body limit: history truncates response_body at 64 KB with a [truncated N chars] marker, keeping the database small
  • Vault — safe key rotation: rotate now updates only the source that holds the key (keyring or .vault_key); a keyring hiccup no longer leaves the vault unreadable on the next boot
  • Vault — key source in stats: vault.stats() reports key_source next to mode
  • Collections — history masking: collection runs store the raw template in history, so Authorization, X-API-Key and similar headers never reach the history table with resolved secrets
  • Collections — concurrent-safe run log: the _runs.json file is now written under a lock; simultaneous GUI and CLI runs no longer drop entries
  • Collections — smarter JSON assertions: json_equals is compared by type first, so true vs "true" and 5 vs "5" behave as expected
  • Encoder / Decoder — per-row XOR key: the key is now a field next to the operation instead of a pop-up dialog; typing in the input no longer spawns a modal on every keystroke
  • Encoder / Decoder — dynamic visibility: the key field appears only when the row's operation is XOR hex
  • JWT Decoder — faster brute force: secret guesses no longer do a linear lookup per hit
  • Reporter — HTML escaping: every user-controlled value in HTML reports is escaped; a malicious </script> in a response body can no longer execute when the report is opened in a browser
  • Reporter — Markdown escaping: grouped reports escape | inside the status column, not only in the URL
  • WebSocket Client — serialized sends: outgoing frames and pings from different threads are ordered, eliminating the rare dropped-frame race
v1.1.0 latest 2026-10-15

WebSocket Client, session management, hardening.

  • New module — WebSocket Client: ws:// and wss://, custom headers, subprotocols, SSL toggle
  • WS messages: text and binary frames, hex dump for binary, per-message detail pane
  • WS history: timeline with direction, opcode, size, timestamp, payload preview
  • WS ping / pong: configurable interval and timeout, manual PING button
  • WS proxy: auto-uses the active proxy from Proxy Manager (HTTP/HTTPS/SOCKS4/SOCKS5)
  • WS vault: {{vault.key}} substitution in URL and headers
  • WS events: ws.opened, ws.closed, ws.message, ws.error on the bus
  • WS services: ws.connect, ws.send, ws.close, ws.ping, ws.list, ws.available, ws.wait_connected, ws.exchange, ws.recent
  • WS integration: open/close writes to History as method="WS"; usable from Collections and System Test
  • HTTP Client — session manager: SessionStore with LRU eviction (max 64), keyed by engine and name, so switching engines no longer loses cookies
  • HTTP Client — cookie editor: add, edit, delete, import JSON, export JSON, per-session
  • HTTP Client — sessions dialog: list all live sessions with cookie counts, clear one or clear all
  • HTTP Client — new services: http.sessions.list, http.sessions.clear_one, http.sessions.clear
  • HTTP Client — header validation: non-latin-1 headers caught before sending with a clear message
  • HTTP Client — URL validation: placeholder and non-ASCII checks in the service itself
  • HTTP Client — cancel button: long requests can be aborted from the same button that sends them
  • HTTP Client — TTFB timing: status line now shows total time and time-to-first-byte
  • HTTP Client — logging: silent except: pass blocks replaced with _log() to console
  • Collections — WebSocket requests: new protocol field (http / ws). WS requests can connect, send, wait for a reply, run assertions, extract to vault and close. Options: ws_binary, ws_timeout, ws_close, ws_reuse_key
  • Collections — configurable parallel workers: parallel_workers (default 5), editable in UI and via CLI --workers
  • Collections — bounded re-auth: max_reauth (default 2) prevents the infinite reauth loop on a persistent 401
  • Collections — per-collection HTTP sessions: session_name="coll:<name>", so parallel runs no longer mix cookies
  • Collections — new template: ws-echo (works against wss://echo.websocket.events)
  • Collections — CLI: added --workers, --parallel, --stop-on-error; output shows [HTTP] / [WS] prefix and [skip] marker
v1.0.0 stable 2026-09-01

First stable release. Shared bus, unified UI, modular toolkit.

  • HTTP Client: three engines (requests, curl_cffi, cloudscraper), cookie jar, redirect chain, hex dump, HTML tree, profiles, curl import/export
  • Port Scanner: TCP/UDP scan, SYN mode, OS fingerprinting via TTL, banner grabbing, service detection
  • DNS Lookup: A, AAAA, CNAME, MX, NS, TXT, SOA, SRV, CAA, PTR; custom nameserver, IPv4/IPv6, reverse lookup
  • Scanner: directory brute-force, soft-404 wildcard filter, extension fuzzing, User-Agent rotation
  • Collections: request sets with assertions, extract to vault, retry/delay, parallel runs, data-driven runs, CLI runner, auto re-auth with TOTP
  • Login Flow: JSON / form-data / Basic / OAuth2, two-step 2FA flow, token auto-detection, CAPTCHA hook
  • JWT Decoder: parse, signature verification, secret brute-force, generation, none-attack, live expiry timer
  • Vault: encrypted Fernet vault with TTL, namespaces, key rotation, bulk import/export
  • Encoder / Decoder: pipeline of 31 operations — Base64/32/58, URL, Hex, HTML, ROT13, Unicode, Gzip, XOR, hashes
  • Diff: unified, side-by-side, word-level; JSON / XML / YAML; ignore whitespace / case / dynamic keys
  • Proxy Manager: parallel checks, dead-proxy auto-disable, latency stats, rotation
  • Reporter: Markdown / HTML / JSON / PDF with filters, status chart, snapshot comparison
  • System Test: end-to-end self-check with embedded Flask server and test HTTP proxy
